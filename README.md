# ЭНДОСКОП — рентген-камера для ИИ-агентов

Наблюдает, что реально делают процессы и агенты на машине, и сверяет
заявления агента с дневником правды.

Три глаза. На Windows, если процесс запущен с правами администратора,
вместо опроса работает ETW (Event Tracing for Windows): старт и выход
процесса, создание/запись/удаление файла в наблюдаемых папках, TCP connect
и первый UDP send. Без прав администратора сессия ядра не поднимается —
эндоскоп сам остаётся на опросе и пишет в лог, какой режим активен.
`ENDOSCOPE_MODE=poll` принудительно оставляет опрос.

| Глаз | Linux | Windows, опрос | Windows, ETW |
|------|-------|----------------|--------------|
| №1 процессы | `/proc` | `toolhelp32` | Microsoft-Windows-Kernel-Process |
| №2 сеть | `/proc/net/tcp` | `iphlpapi` | Microsoft-Windows-Kernel-Network |
| №3 файлы | mtime | mtime | Microsoft-Windows-Kernel-File |

Команда агента берётся из `/proc/<pid>/cmdline` на Linux и из PEB
(`NtQueryInformationProcess`) на Windows. Классическая ETW-сессия процесса,
если она поднялась, отдаёт ту же командную строку, пока процесс ещё жив.
Кто именно держит файл открытым — из `/proc/<pid>/fd` на Linux и через
Restart Manager (`RmStartSession`/`RmGetList`) на Windows. Это нужно опросу
файлов; в режиме ETW путь приходит вместе с событием.

IPv4 из таблицы TCP и из ETW печатается в обычном порядке (`127.0.0.1`,
не `1.0.0.127`). В поле `agent` пишется имя образа (`notepad.exe`) и рядом
pid и родитель. Прежний класс `process` / `tool` / `ai-agent` остаётся
в поле `class`.

## Запуск

```
endoscope.exe
```

Чтобы ETW реально видел короткие процессы, нужен повышенный токен.
Из уже повышенной консоли достаточно просто запустить exe. Чтобы глаз
поднимался при входе в систему, задача планировщика с высшими правами:

```
schtasks /Create /TN Endoscope /SC ONLOGON /RL HIGHEST /F /TR "C:\path\endoscope.exe"
```

`/RL HIGHEST` — это «выполнять с наивысшими правами». Без этого в логе
будет `режим=poll`, а в `/health` поле `"mode":"poll"`.

- экран «кино»: <http://127.0.0.1:7095>
- журнал правды: `endoscope.jsonl` (JSONL, одна строка — один факт)

Переменные окружения:

| Переменная | Смысл |
|------------|-------|
| `ENDOSCOPE_JOURNAL` | путь к журналу (по умолчанию `endoscope.jsonl`) |
| `ENDOSCOPE_WATCH_DIRS` | папки под наблюдением; на Windows — через `;`, на Linux — через `:` |
| `ENDOSCOPE_MODE` | `poll` — не поднимать ETW даже у администратора |

Если `ENDOSCOPE_WATCH_DIRS` не задан, на Windows смотрятся `C:\remote` и
профиль пользователя (`USERPROFILE`). Шум отбрасывается: `target`, `.git`,
`node_modules`, temp, кэши Chrome/Edge и соседние кэши. Каталог
`C:\remote\temp` шумом не считается. На Linux список папок тот же, что в v0.7.

## API экрана

| Запрос | Ответ |
|--------|-------|
| `GET /` | страница с живой лентой |
| `GET /events` | последние 100 фактов журнала (JSON) |
| `GET /health` | `ok`, `version`, `mode` (`etw` или `poll`), путь журнала |
| `GET /frame` | живой кадр: процессы, слушающие порты и хвост журнала |
| `GET /check?path=<путь>` | правда по пути: трогали или нет |
| `GET /lie?claim=<заявление>` | детектор лжи: СОВРАЛ / ПРАВДА / ПОДТВЕРЖДЕНО |

`/frame` совместим с кадром 0.8.1: у процесса есть `pid`, `cmd`, `agent`
(класс, не имя файла), у порта — `pid`, `port`, `local`. Добавлены `image`,
`ppid` и `mode`.

Пример: агент заявляет «я не трогал C:\work\file.txt», а файл в журнале есть —
детектор отдаёт `ВРАНЬЁ ОБНАРУЖЕНО` и показывает доказательство.

Строка журнала по-прежнему содержит `ts`, `kind`, `pid`, `agent`, `detail`.
К ним добавлены, без переименования старых полей:

| Поле | Смысл |
|------|-------|
| `agent` | имя образа (`notepad.exe`); если имени нет — прежний класс |
| `image` | то же имя образа, пустая строка если неизвестно |
| `ppid` | pid родителя |
| `cmdline` | командная строка |
| `class` | `process` / `tool` / `ai-agent` / `unknown` |
| `source` | `etw` или `poll` |

`kind` тот же набор плюс `exit` (процесс завершился). `detail` у файла —
путь, у TCP — `-> ip:port`, у UDP — `udp -> ip:port`, у запуска —
командная строка. Старые строки журнала без новых полей читаются как раньше.
Первый снимок при старте всегда пишется опросом (`"source":"poll"`): так
уже лежащие файлы попадают в журнал. Дальше, если ETW поднялся, новые факты
идут с `"source":"etw"`.
Одинаковые факты сжимаются: файлы — 1 с, TCP — 5 с, UDP — 30 с, запуск и
выход — 2 с, и не больше 120 событий в секунду.

## Сборка

Локально на Windows нужен MSVC (линкер `link.exe`); в проекте нет MSVC —
собирает CI:

- `.github/workflows/build.yml` — сборка на `windows-latest` (MSVC) и
  `ubuntu-latest`, плюс дым-тест: экран поднимается, лента живёт, детектор
  лжи ловит ложь и не ловит правду.

Артефакты: `endoscope-windows-x64`, `endoscope-linux-x64`.
